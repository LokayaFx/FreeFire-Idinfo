# Free Fire OB55 compatibility research

Date: 2026-09-27. Local research only; application source has not been patched.

Repositories inspected:
- FreeFireInfoSite: commit `0c2b0d7`
- free-fire-php-monorepo: commit `9788239`

## Finding

The immediate failure is an OB55 protocol compatibility problem, not evidence that the entire login service is down. The existing OB54 request receives HTTP 503. Changing only ReleaseVersion to OB55 receives HTTP 400. With OB55 plus X-GA-SV set to the current Unix timestamp, login succeeds. Successful login responses observed have a 64-byte prefix before the Protobuf message. Removing that prefix allows the existing login schema to decode the token, region, server URL and TTL.

A complete BD lookup succeeded using the existing request encryption and player-response schema. No external JWT service, borrowed token, registration or account modification was used.

## Controlled comparisons

The same existing BD/global guest account and four-field login request were used. Credentials and tokens were kept in process memory; outputs contain status/field-presence metadata only.

| Request | Result |
| --- | --- |
| Original host, OB54, original headers | HTTP 503, HTML |
| Original host, OB55, original headers | HTTP 400 |
| New host, OB55, original headers | HTTP 400 |
| New host, OB55, community header set | HTTP 200; raw Protobuf parse fails |
| Original host, OB55, community header set | HTTP 200; raw Protobuf parse fails |
| Successful response with first 64 bytes removed | Existing LoginRes schema parses; token and server are present |
| Community header set without X-GA-SV | HTTP 400 |
| Community header set with current Unix timestamp as X-GA-SV | HTTP 200, valid token |
| Revert only user agent to original Dalvik | HTTP 200, valid token |
| Revert only Unity header to 2018.4.11f1 | HTTP 200, valid token |
| Revert only content type to application/octet-stream | HTTP 200, valid token |
| Remove Expect header | HTTP 200, valid token |
| Original host AND original headers, add OB55 and current X-GA-SV, decode after 64-byte prefix | Valid login and successful BD player lookup |

This isolates the necessary changes for the tested path. It does not establish that the server validates X-GA-SV as a timestamp, what its allowed clock-skew range is, or that every future response will use the same framing. Do not copy a fixed timestamp from community code into production.

BR and VN returned 78-byte bodies. After removing the observed prefix, the existing schema decoded only queue_info with allow=true. These are not usable logins. This is NOT evidence of an account ban, invalid password, or a definitive credential-rotation requirement. Queue semantics and retry behavior need further validation before enabling those groups.

BD/global returning SG is gateway routing: the subsequent player response correctly returned region BD.

Successful token TTL was 28,800 seconds. The current Python cache uses 25,200 seconds, which is shorter; this did not cause the outage.

## End-to-end player result

Using the existing UI example UID, the corrected request flow reached the server supplied by MajorLogin and received HTTP 200. The original player schema parsed the response from offset zero; it did NOT require removing 64 bytes.

The returned data contained a nickname and these sections: basicInfo, profileInfo, clanBasicInfo, captainBasicInfo, petInfo, socialInfo, diamondCostRes, creditScoreInfo. Player region was BD. Raw player data was not saved.

Observed returned server hosts were clientbp.ppmainecoonghj.com, client.ind.freefiremobile.com and client.us.freefiremobile.com. Both loginbp.ggblueshark.com and loginbp.ppmainecoonghj.com passed normal TLS checks and resolved to the same address pool during the test. The old host worked with the corrected request, so changing the hostname alone is neither necessary for this tested path nor sufficient to fix the current code. Continue using the validated player server returned by login.

## Mapping to the monorepo update guide

Read: OB_UPDATE_GUIDE.md, OB_PROTOCOL_CAPTURE.md, LIVE_PROTOCOL_VERIFICATION.md, PROTOCOL_RECOVERY.md, TOKEN_GENERATION_FLOW.md and protocol/ob54/RECOVERY_NOTES.md.

The recovery notes explicitly say OB54 schemas were reconstructed from FreeFireInfoSite's old generated Python modules and live response verification remained a release gate. An OB label in the repository does not establish live compatibility.

Recommended implementation, following that guide:

1. Preserve Ob54ProtocolProfile and add an opt-in Ob55ProtocolProfile; register it in BuiltInProtocolProfiles. Keep old rollback configuration available.
2. Add the verified OB55 header behavior. Generate X-GA-SV per request; keep the clock dependency testable. Record the endpoint and client identity separately from unverified official-build provenance.
3. Add version-specific login framing handling before LoginResponseDecoder. Validate body size and decoded required fields. Avoid unconditional slicing of every binary response, arbitrary offset scanning or accepting a JWT substring as a complete login.
4. Keep player decoding separate: the tested player response was plain Protobuf with no prefix. Do not silently alter generated schema fields based on community names. Obtain the exact client descriptors and classify differences before claiming complete OB55 schema support.
5. Add synthetic fixtures for framed login success, truncated frames, malformed messages, missing token/server and queue-only replies. Compare Python and PHP login/player request bytes and AES ciphertext with non-secret fixture inputs.
6. Preserve upstream errors: authentication/protocol failure must not become player-not-found. Handle queue responses distinctly and use bounded, observable retry behavior only after its semantics are understood.
7. Run offline PHP/Laravel checks and the guide's live matrix before releasing. This investigation tested the Python reference flow, not a patched PHP implementation.

Python change locations: app.py ReleaseVersion (line 27), login request headers and decode (lines 97-100), token validation/cache (lines 101-105), player request headers (line 148), swallowed auto-region errors (line 200), misleading not-found (line 213).

PHP change locations: packages/core/src/Protocol/Profiles/, Protocol/BuiltInProtocolProfiles.php, Protocol/LoginResponseDecoder.php, Token/TokenManager.php and protocol-version fixtures/tests. Laravel/starter UI changes are not inherently required for this protocol fix.
